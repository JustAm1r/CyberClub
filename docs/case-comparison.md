# Сравнение моделей поставки для трёх кейсов

## Кейс 1. Внедрение ИС документооборота в государственном органе

**Выбранная модель: Predictive**

| Критерий | Обоснование |
|---|---|
| Неопределённость требований | Низкая. Основные требования заранее определены в тендерной документации |
| Стоимость ошибки | Высокая. Ошибка может привести к непринятию системы |
| Регуляторика | Высокая. Необходимо соблюдать требования госоргана и законодательства |
| Зрелость заказчика | Работа строится через формальные согласования |
| Команда | Роли и задачи желательно определить заранее |
| Тип контракта | Обычно фиксированы объём работ, сроки и стоимость |

**Вывод:** Predictive подходит лучше всего, потому что требования и результат в основном определены заранее.

## Кейс 2. Новый мобильный продукт стартапа с непроверенной гипотезой

**Выбранная модель: Adaptive**

| Критерий | Обоснование |
|---|---|
| Неопределённость требований | Очень высокая. Неизвестно, какие функции действительно нужны пользователям |
| Стоимость ошибки | Лучше проверить идею на небольшом MVP, чем сразу разрабатывать весь продукт |
| Регуляторика | Обычно невысокая |
| Зрелость заказчика | Стартап может быстро менять требования на основе обратной связи |
| Команда | Небольшая команда может быстро менять приоритеты |
| Тип контракта | Жёстко фиксированный объём работ обычно отсутствует |

**Вывод:** Adaptive подходит лучше всего, потому что продукт нужно развивать небольшими итерациями и проверять гипотезы на пользователях.

## Кейс 3. Миграция монолита банка в облако

**Выбранная модель: Hybrid**

| Критерий | Обоснование |
|---|---|
| Неопределённость требований | Средняя. Цель понятна, но технические проблемы могут появляться в процессе миграции |
| Стоимость ошибки | Очень высокая. Ошибка может привести к остановке банковских сервисов |
| Регуляторика | Высокая. Важны безопасность и защита клиентских данных |
| Зрелость заказчика | Требуются строгий контроль, согласования и отчётность |
| Команда | Несколько технических подразделений должны работать согласованно |
| Тип контракта | Общий результат и сроки могут быть фиксированы, а технические работы выполняются итерациями |

**Вывод:** Hybrid подходит лучше всего: основные требования, безопасность и контроль фиксируются заранее, а техническая миграция выполняется поэтапно.

---

## Итог

| Кейс | Модель поставки | Основная причина |
|---|---|---|
| ИС документооборота в госоргане | Predictive | Заранее определённые требования и формальная приёмка |
| Мобильный продукт стартапа | Adaptive | Высокая неопределённость и необходимость проверки гипотез |
| Миграция банка в облако | Hybrid | Необходим строгий контроль, но технические работы лучше выполнять поэтапно |
