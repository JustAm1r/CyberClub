# Лабораторная работа №4

## Проект: CyberClub

CyberClub — информационная система для бронирования и управления компьютерным клубом.

Цель лабораторной работы — определить заинтересованные стороны, собрать требования пользователей, сформировать MVP, backlog и нефункциональные требования системы.

---

## Выполненные части

### 1. Заинтересованные стороны

Определены основные заинтересованные стороны проекта:

- владелец компьютерного клуба;
- администратор;
- клиент;
- разработчик / Project Manager.

Составлена матрица «Влияние — Интерес» и план коммуникаций.

[Открыть анализ заинтересованных сторон](stakeholders.md)

---

### 2. Интервью с пользователями

Подготовлены вопросы для двух интервью с потенциальными пользователями CyberClub.

Цель интервью — проверить предположения о проблемах бронирования и определить действительно необходимые функции.

[Открыть интервью](interviews.md)

---

### 3. Story Map

Построена Story Map пользовательского пути:

Регистрация → Просмотр компьютеров → Выбор времени → Выбор тарифа → Бронирование → Управление бронированием

Также выделен MVP — минимальный набор функций первой версии системы.

[Открыть Story Map](story-map/)

---

### 4. MVP

В первую версию CyberClub входят:

- регистрация и вход;
- просмотр списка компьютеров;
- просмотр статусов компьютеров;
- выбор даты и времени;
- просмотр свободных интервалов;
- просмотр и выбор тарифа;
- создание бронирования;
- просмотр своих бронирований;
- отмена бронирования.

После MVP могут быть добавлены:

- подробные характеристики ПК;
- история бронирований;
- изменение существующего бронирования;
- уведомления;
- онлайн-оплата;
- бонусная система;
- промокоды и скидки;
- статистика и аналитика.

---

### 5. Backlog

В GitHub Projects сформирован backlog проекта.

Для User Stories используются:

- Epic;
- Acceptance Criteria;
- Priority;
- Estimate;
- Task Type.

Основной рабочий процесс:

Backlog → To Do → In Progress → Review → Done

### 6. Нефункциональные требования

Для CyberClub сформулированы измеримые требования по:

- производительности;
- доступности;
- безопасности;
- надёжности;

- журналированию;

## Итог

В лабораторной работе были определены основные пользователи CyberClub и их потребности.

Story Map позволила показать путь пользователя, а MVP — определить минимальный набор функций первой версии системы.

User Stories переводят потребности пользователей в задачи разработки, а нефункциональные требования определяют качество, безопасность и производительность системы.
